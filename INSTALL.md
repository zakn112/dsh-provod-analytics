# Плагин «Расходы Provod» — установка на другом компьютере

Инструкция рассчитана на агента DSH: каждый шаг проверяем, у каждого действия есть ожидаемый результат.
Человеку достаточно разделов «Требования», «Шаг 4» и «Диагностика».

## Что это

Панель **«Расходы»** в списке панелей левого столбца (внутренний id `provod-analytics`). Показывает расходы
рабочего пространства Provod: остаток на счёте, суммы за сегодня и с начала месяца, прогноз до конца месяца,
расходы по дням, разбивку по моделям с диаграммами (ТОП-10 и «Показать все») и эффективность моделей.

Данные берутся из `POST /v1/analytics/query` и `GET /v1/balance` на `https://api.provod.ai`. Запросы делает
Host: ключ в браузер не попадает.

## Требования

- DSH **0.2.2-rc.5** с Web-интерфейсом (Desktop или `dsh web`). На других версиях не проверялось.
- **Управляющий ключ** рабочего пространства Provod (management key). Обычный ключ к аналитике не допускается.
- **Обычный API-ключ** Provod (`PROVOD_API_KEY`) — необязателен, но только с ним карточка баланса показывает
  точный остаток после резервов. Без него показывается оценка «пополнения минус расходы» с пометкой «≈».
- Сетевой доступ с машины к `https://api.provod.ai`.
- Node.js 20 или новее — только для шага 6 (тесты). Для установки и работы не требуется.

## Шаг 1. Распаковать архив

Каталог назначения должен быть **постоянным** (не временным каталогом и не папкой распаковки архиватора):
при установке DSH закрепляет путь к пакету, и удаление каталога ломает плагин.

На верхнем уровне каталога должен лежать `package.json` пакета `dsh-provod-analytics`:

```text
<плагины>/
  dsh-provod-analytics/
    package.json
    index.js
    client.js
    cordis.patch.yml
    lib/
    locale/
    docs/
    tools/
```

Проверка (Linux/macOS):

```sh
test -f "<каталог>/dsh-provod-analytics/package.json" && echo ok
```

Проверка (Windows PowerShell):

```powershell
Test-Path "<каталог>\dsh-provod-analytics\package.json"
```

Ожидаемо: `ok` или `True`.

## Шаг 2. Установить бандл

Агент вызывает инструмент `plugin_manager`:

- `action`: `install_bundle`
- `target`: абсолютный путь к каталогу `dsh-provod-analytics` (не к архиву и не к `package.json`)

Ожидаемый результат: `"application": "applied"` и пустой `warnings`. Если `application` другой — читать
`nextStep` и `error` в том же ответе; чаще всего это конфликт имени пакета или недоступный каталог.

Без инструмента `plugin_manager`: в интерфейсе DSH — **Plugins → Add plugin** и указать тот же каталог.

Установка ничего не скачивает из сети: пакет локальный, зависимостей у него нет.

## Шаг 3. Проверить регистрацию

1. `plugin_manager`, `action: list_plugins` → в списке есть запись `entryId: "include:dsh-provod-analytics"`
   с `enabled: true`.
2. `cordis_inspect_query`, `platform: client`, `provider: Slots`, `method: listSubTree`,
   `input: { "root": "sidebar.panellist" }` → в `selected.occupants` есть `{ "id": "provod-analytics",
   "order": 20, "active": true }`.
3. То же с `input: { "root": "main" }` → в `occupants` есть ключ `provod-analytics` с `active: true`.

Пункт 2 подтверждает, что клиентская половина загрузилась в браузере; пункт 3 — что страница
зарегистрирована. Если записей нет: перезагрузить страницу DSH и повторить, затем перезапустить DSH.

## Шаг 4. Задать ключ Provod

**Вариант A, через интерфейс (предпочтительно).** Открыть панель «Расходы», вставить ключ в поле
«Управляющий ключ» и нажать «Сохранить ключ». Значение ложится в хранилище учётных данных DSH
и в браузер не возвращается.

**Вариант B, для агента без доступа к интерфейсу.** Задать переменную окружения
`PROVOD_MANAGEMENT_API_KEY` в окружении процесса DSH и перезапустить DSH — ключ читается оттуда.
Команда для запуска из терминала (Linux/macOS):

```sh
PROVOD_MANAGEMENT_API_KEY='<ключ>' dsh web
```

**Чего делать не нужно:** класть ключ в файлы плагина или в `cordis.patch.yml`. Плагину это не требуется,
а секрет окажется в копиях и резервных копиях профиля.

**Обычный ключ для точного баланса.** `/v1/balance` — inference-эндпоинт: управляющему ключу он отвечает
`403`. Если в хранилище учётных данных DSH есть запись `PROVOD_API_KEY` (её использует провайдер моделей)
или задана такая переменная окружения, панель берёт точный остаток. Иначе показывается оценка
«пополнения минус расходы» из `GET /v1/credits` с пометкой «≈»: она не учитывает резервы и возвраты.

## Шаг 5. Проверить данные

1. Перезагрузить страницу DSH (Ctrl+R, на macOS Cmd+R).
2. Открыть «Расходы». Ожидаемо: карточки остатка на счёте, расходов за сегодня и с начала месяца,
   прогноз до конца месяца, полоса по дням, две диаграммы по моделям, таблица ТОП-10 расходов
   с кнопкой «Показать все» и таблица эффективности моделей.
3. Если панель показывает «Не удалось получить данные» — это ответ Provod, а не сбой плагина.
   Текст ошибки указывает причину: `401` — ключ неверный или отозван, `403` — ключ не управляющий,
   `429` — превышен лимит (2 запроса в секунду, 30 в минуту), `503` — аналитика временно недоступна.
4. Если видны карточки и диаграммы, но нет прогноза, полосы по дням и эффективности, а карточка
   баланса показывает прочерк — Host не подхватил новый код: перезапустить DSH. Клиентская
   половина такие блоки просто скрывает, ошибки не будет.

## Шаг 6. Автотесты (необязательно)

Проверяют логику без запуска DSH: разбор ответа API, арифметику сумм и границ периодов, маршруты Host.

```sh
cd "<каталог>/dsh-provod-analytics"
node tools/test-core.mjs     # 33 проверки
node tools/test-server.mjs   # 11 проверок
node tools/test-client.mjs   # 1 проверка
```

Все три команды должны завершиться с кодом 0 и напечатать «проверок пройдено» в конце.

## Диагностика

| Симптом | Вероятная причина | Действие |
|---|---|---|
| Пункта «Расходы» нет в списке панелей | строка не создана, страница не перезагружена | шаг 3, затем Ctrl+R, затем перезапуск DSH |
| Панель открывается, но просит ключ | ключ не задан | шаг 4 |
| «Ключ не принят: он неверный, отключён или истёк» | ответ 401 | проверить ключ в кабинете Provod |
| «Ключ не подходит: нужен управляющий ключ» | ответ 403, обычный ключ | создать управляющий ключ |
| «Слишком часто: лимит 2 запроса в секунду» | ответ 429 | подождать минуту, обновить |
| «Аналитика временно недоступна» | ответ 503 | повторить позже |
| Нет блоков прогноза, дней, эффективности или баланса | Host работает на старом коде | перезапустить DSH |
| `install_bundle` не дал `applied` | путь, права или конфликт имени | смотреть `nextStep` и `error` в ответе |
| Работало и перестало после переноса каталога | каталог плагина перемещён или удалён | установить заново из постоянного каталога |

## Удаление

`plugin_manager`, `action: remove_bundle`, `target: "dsh-provod-analytics"`; либо в интерфейсе
**Plugins** → удалить бандл. Удаление убирает панель и маршруты. Ключ в хранилище учётных данных
при этом остаётся — его удаляют кнопкой «Удалить ключ» в панели, если он больше не нужен.

## Что плагин делает с данными

Это важно проверить перед установкой на чужой машине.

- Host регистрирует один маршрут-префикс `/provod-analytics/api` с операциями `status`, `report`, `key`.
  Он закрыт той же проверкой доверия соединения, что и остальные маршруты приложения: сторонний клиент
  получает отказ.
- За одно обновление панель делает до пяти запросов к `api.provod.ai`: `GET /v1/balance` обычным ключом
  (точный остаток) либо `GET /v1/credits` управляющим (оценка, если обычного ключа нет), и три
  `POST /v1/analytics/query` — текущие сутки, месяц и почасовой разрез месяца. Передаются только ключи
  и диапазоны дат — ни текстов запросов, ни данных сессий.
- Журнал сессий DSH не читается и не изменяется; файлы вне каталога плагина не пишутся.
- Ключ хранится в хранилище учётных данных DSH и никогда не возвращается в браузер.
- Секретов и ключей в архиве нет.

## Как передать задачу агенту

Пользователь может вставить агенту такой текст:

```text
Установи плагин «Расходы Provod» из архива dsh-provod-analytics-0.2.1.zip по инструкции INSTALL.md
внутри него: распакуй в постоянный каталог, установи через plugin_manager install_bundle, проверь
регистрацию панели по шагу 3 и сообщи результат. Ключ Provod я введу сам в панели.
```
